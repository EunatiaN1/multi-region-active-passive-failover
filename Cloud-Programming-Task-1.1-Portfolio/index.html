Resilience strategy

Two layers, different failure modes.

Fast application-level recovery comes first. DNS failover provides a separate route when the primary region itself is unavailable.

01

Edge origin failover

CloudFront monitors the primary ALB origin. On configured origin failures, its origin group serves the S3 maintenance page without waiting for DNS propagation.

  • Handles primary origin errors
  • Routes at the CloudFront edge
  • Requires a configured secondary origin
02

Regional DNS failover

Route 53 health-checks the public endpoint and switches the failover record to the standby S3 website endpoint if the primary is unhealthy.

  • Provides a path around regional failure
  • Example: 10-second checks, 3 failed checks
  • Recovery depends on health checks and DNS caching

Design notes

Keeping the standby page static avoids running a second application fleet. The two failover layers are independently useful and should be exercised separately during testing.

Operational considerations

CloudFront distribution changes can take time to deploy. Keep health checks public and verify the S3 website access policy and failover behavior for your own security requirements.
